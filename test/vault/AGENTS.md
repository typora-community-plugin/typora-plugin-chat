# AGENTS.md

本文件是 Vault 中 Agent（AI 助手）的行为规范。每次会话开始时，Agent 应阅读此文件并遵循其中的规则。

## 核心原则：渐进式探索

> **不要一次性加载过多内容到上下文。**

- **逐层深入**：先列出目录结构，了解整体布局；再根据任务需要，按需打开具体文件。
- **最小读取**：只读取与当前任务直接相关的文件。避免"预防性阅读"（即"可能用得上所以读一下"）。
- **分页处理大文件**：对于长文档，先浏览标题/结构，确认相关章节后再精读。
- **及时丢弃**：已读完且不再需要的文件内容，不要反复引用或复制到其他文件中。
- **并行探索有度**：可以并行读取少量相关文件（≤3 个），但不要同时拉取整个目录的文件内容。

### 推荐流程

```
1. list_files          → 了解顶层结构
2. read AGENTS.md      → 确认行为规范
3. search_vault        → 按关键词定位目标文件
4. read (单个文件)     → 精读目标
5. edit / create       → 执行操作
6. （必要时）再探索    → 发现新线索后继续第 2-4 步
```

## Frontmatter 规范

每个 Markdown 文件必须包含以下 frontmatter：

```yaml
---
created: <ISO 8601 DateTime>   # 文件创建时间，一经设定不再修改
updated: <ISO 8601 DateTime>   # 最近一次内容变更时间
focused: <HH:MM:SS>            # Agent 对该文件的累计聚焦时长（时:分:秒）
---
```

### 字段说明

| 字段 | 何时写入/更新 |
|------|-------------|
| `created` | 仅在创建新文件时写入，之后永不修改 |
| `updated` | 每次对文件内容做实质性修改（edit_document / create_file）后更新为当前时间 |
| `focused` | 记录 Agent 对该文件的**累计聚焦时长**。格式 `HH:MM:SS`（如 `01:23:45`）。每次 Agent 主动打开并阅读该文件时，累加本次会话中停留在此文件上的时间；仅 list_files 或 search_vault 命中不算 |

### 格式要求

- 使用 ISO 8601 带时区偏移，例如 `2026-08-31T21:15:58+08:00`
- 时间取 Agent 执行操作时的本地时区（通过 get_current_datetime 获取）
- frontmatter 位于文件最顶部，用 `---` 包裹

## 其他约定

- 新建文件必须带完整 frontmatter。
- 编辑已有文件若缺少 frontmatter，应顺手补全（created 和 updated 均取当前时间，focused 也取当前时间）。
- 不要删除或重命名已有的 frontmatter 字段。
